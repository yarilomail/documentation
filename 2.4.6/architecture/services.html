Services configuration ​

The services section controls which listeners are started and how each one behaves at the network level. Each entry is named after the process that reads it: the *_login entries are the login proxies', which alone terminate client TLS, and the bare names are the session backends', one plain listener each. A process reads its own entries only: one it needs that is missing stops its start, naming the key. enabled: false leaves the listener off.

Common fields ​

All services share the following fields:

enabled ​

Default
false
Type
boolean

Start this listener on startup.

address ​

Default
127.0.0.1 on a session backend and on yarilo; every interface on a login proxy
Type
string
See also
port
Added
2.4.6

Host the listener binds. Empty leaves it to the process that binds it: a session backend entry (imap, pop3, submission, lmtp, managesieve, jmap) binds 127.0.0.1, in its own binary and in the single yarilo binary alike, since a backend takes logins only through a login proxy; a login proxy's *_login entry binds every interface. Each listener logs the address it bound and whether it came from this key or from the role. The Helm chart and the compose example set 0.0.0.0, every interface.

port ​

Default
0
Type
integer

TCP port to bind. Required: there is no default, and an unset port binds port 0, a random one. The table below gives the conventional ports.

ssl_mode ​

Default
none
Type
string
Values
ssl starttls no

TLS mode: ssl is implicit TLS; starttls is plain with a STARTTLS upgrade; no is plain only.

haproxy_protocol ​

Default
false
Type
boolean
See also
timeout

Extract the real client IP from the HAProxy PROXY header. Uses general.haproxy for the timeout and trusted nets.

xclient_protocol ​

Default
false
Type
boolean

Accept the XCLIENT command from trusted relays. Uses general.xclient.trusted_nets, empty by default; only peers in it see XCLIENT advertised.

auth_allow_cleartext ​

Default
true
Type
boolean

When false, PLAIN and LOGIN are hidden and refused on a connection that is not TLS, not behind HAProxy and not local: IMAP LOGIN/AUTHENTICATE get NO [PRIVACYREQUIRED], POP3 USER/PASS/AUTH -ERR [AUTH], SMTP AUTH 523 5.7.10, ManageSieve AUTHENTICATE NO "Cleartext authentication disallowed on non-secure (SSL/TLS) connections.". After STARTTLS they work as usual.

A service may also carry ssl, a per-service SSL override with the same fields as general.ssl; it overrides only the fields it sets.

Renamed with an inverted sense

auth_allow_cleartext replaces the pre-beta disable_plaintext_auth, and the meaning is flipped: auth_allow_cleartext: false is what disable_plaintext_auth: true used to say. The old key is still accepted on its own. Setting both keys on one listener refuses startup - even when their values agree - because a config carrying both is one edit away from meaning the opposite of what it says.

Internal services ​

Outside k8s, the internal services listen on 127.0.0.1 unless the config names an address, and so does a session backend whose address is empty. A host install that reaches any of them from another host sets the address explicitly. The Helm chart sets every one of them, so a release listens as before. The director's ring and API (director_service.listen) and the quota policy service (quota_status.listen) follow the same rule.

Unix sockets ​

On one host, yarilo-auth, yarilo-warden and yarilo-dict can listen on Unix sockets instead: a listen or dial address written unix:/path is a socket, and yarilo-locks in embedded mode uses one already.

  • The socket gets its mode and group after the bind, so the umask does not decide them. A group that does not exist, or that the process may not give the socket, stops the start.
  • A socket file left by a process that is gone is replaced. One a running process answers on is left to it and the start fails, so a second instance cannot take it; a path that is not a socket is never removed.
  • internal_tls does not apply to a socket, on either side: its permissions are the boundary. With internal_tls on, the process logs that once per address.
  • The master listener issues sessions without a password. On a socket, yarilo-auth reads the peer's uid from the kernel and issues one only to the users in auth_service.master_session_users, so a login proxy that can reach the socket still cannot issue itself a session.

Examples ​

A whole host, with every process reading one file, is in One host.

IMAP login proxy behind HAProxy ​

yaml
services:
  imaps_login:
    enabled: true
    port: 993
    ssl_mode: ssl
    haproxy_protocol: true
  imap_login:
    enabled: true
    port: 143
    ssl_mode: starttls
    haproxy_protocol: true
    auth_allow_cleartext: false

Submission login proxy ​

yaml
services:

    port: 587
    ssl_mode: starttls
    auth_allow_cleartext: false
  submissions_login:

LMTP backend (yarilo-lmtp) ​

yaml
services:
  lmtp:
    enabled: true
    port: 10024
    ssl_mode: "no"

Accepts preamble connections from yarilo-lmtp-login only. See LMTP configuration for architecture and lmtp_login_service config.

Per-service TLS certificate override ​

yaml
services:
  imaps_login:
    enabled: true
    port: 993
    ssl_mode: ssl
    ssl:
      ssl_server_cert_file: /etc/ssl/mail.example.com/cert.pem
      ssl_server_key_file:  /etc/ssl/mail.example.com/key.pem
